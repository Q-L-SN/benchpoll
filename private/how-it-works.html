How BenchPoll works

Build your own benchmark mix for any category and context, compare it with Public Weights, and see the model leaderboard those public priorities produce.

01
Scope

Every ranking begins with a specific question

A category identifies the capability being evaluated. Context selectors narrow the evaluation conditions, such as web access, code execution, or model scope. Each category-context combination has its own Personal Weights, Public Weights, and model ranking.

Coding Software Engineering Python Web access: Allowed
No universal weight set

A benchmark can be important for one capability and irrelevant to another. BenchPoll preserves that distinction.

02
Your priorities

Personal Weights are a complete allocation

Your weights for a category and context are either empty or total exactly 100%. Increasing one benchmark necessarily reduces the share available to the others, so the result expresses tradeoffs rather than unlimited approval.

  • Every benchmark test condition is a separate weightable object.
  • A benchmark omitted from your allocation contributes 0%.
  • You can give a weighted Fallback to a benchmark when a model has no direct score.
  • Your personal model ranking updates from your own weights.

03
Community aggregate

Public Weights average people, not raw clicks

BenchPoll averages every valid Personal Weight allocation in the selected category-context scope. A valid allocation is non-empty and totals 100%. Benchmarks absent from a person's allocation count as 0% for that person.

Public weight of benchmark b Wb = (1 / N) Σu=1..N wu,b N is the number of valid Personal Weight allocations in scope.
Equal per person

Each valid allocation has the same total influence.

Subtree aware

The selected category includes matching descendant categories and contexts.

Sample weighted

A context contributes in proportion to its number of valid personal allocations.

04
Scores and uncertainty

Model rankings show what is known and what is missing

Accepted benchmark results are global evidence for one model condition and one benchmark condition. BenchPoll normalizes every accepted sample by that benchmark condition's scale and direction, uses the median when multiple samples exist, and then applies the Personal or Public Weight from the category and context you are viewing. Each model test condition is ranked separately.

Weighted model score Sm = Σb Wb x sm,b

When a result is missing, BenchPoll does not invent a point estimate. The lower bound treats that missing share as 0; the upper bound treats it as 100. Known normalized results remain visible even when custom-scale extrapolation places them outside the conventional 0-100 range.

Fallback applies only to Personal Weights. A direct score for the primary benchmark always takes precedence; otherwise BenchPoll uses direct scores from its fallback mix. Any missing fallback share remains an uncertainty interval rather than becoming an invented zero.

05
Data integrity

Contributions are sourced, reviewed, and correctable

Community members can propose benchmarks, models, test conditions, categories, and model results. Score submissions require a source URL. Submissions enter review before they affect public data or rankings.

  1. 1
    Submit

    Provide structured data and an authoritative source.

  2. 2
    Review

    A reviewer checks the object, source, and proposed database changes.

  3. 3
    Apply

    Accepted changes are logged and become available to the ranking engine.

Designed to be corrected

Existing objects and scores have dedicated change requests, so provenance is preserved instead of silently overwritten.
