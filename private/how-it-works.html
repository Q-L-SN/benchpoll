How BenchPoll works

BenchPoll combines benchmark results into topic-specific model rankings. Compare models using the community’s benchmark weights or set your own.

Topics and scenes

Open a topic to see its public index. Topics group related tasks. Scenes narrow the comparison to a specific goal, such as Python within Coding. A topic can have one level of scenes, with the default scene first. Each scene has its own weights and discussion and shares the topic summary.

Use the topic menu to find favorites, topics you configured or created, recent visits, or search by name. Search shows matching scenes inside their topic card. Favorite topics appear in your profile. Popular topics are ranked by favorites, with recent favorites carrying more weight.

Filters apply to every ranking card. Estimated score is the default. Open a model to see its results and sources.

Benchmark weights

Weights determine how much each evaluation item contributes to an index.

Personal Weights

Add benchmarks or topic references from Evaluation items. A nonempty Index composition adds up to 100%. With two or more items, select a block and scroll over the chart, or drag vertically on a phone, to change its weight. The other shares rebalance.

You can try adjusting weights without signing in. Sign in to save your weights. The page marks unsaved changes.

Public Weights

Public Weights combine saved configurations for the current topic or scene. Each person contributes one configuration, updated as they save edits. Another public topic contributes only through an explicit reference. Private topics and their weights are visible only to their creator.

Which configurations count

BenchPoll uses all nonempty configurations updated for the topic or scene in the past 72 hours. If fewer than 10 qualify, it uses the latest 10 or as many as exist. The same sample determines community scoring version shares and estimation vote counts.

Topic references

To combine topics, add another topic that has saved weights and choose a specific scene if it has scenes. The reference stays linked to that scene’s live weights. Public indices use the referenced scene’s public weights. Personal indices use your saved weights there when available and otherwise use public weights.

Choose a different topic or scene from the one you’re editing. Public topics can reference public topics and scenes. Private topics can reference those and your other private topics.

BenchPoll multiplies weights along each path and adds the shares for each benchmark version. Referenced scenes use their own estimation votes. If references form a loop, BenchPoll includes the benchmark shares reached along repeated paths. Empty or unavailable targets and loops with no path to benchmarks keep their missing weight.

References combine scores across capabilities. For a specific combination, such as real-time vector generation, use benchmarks that test those requirements together.

Scores and rankings

Both modes use the same qualifying measurements, converted using each test’s score range and direction. A direct score on a scoring version takes priority, including zero and negative scores.

BenchPoll uses the best qualifying score per test by default. Turn on effort or harness to rank settings separately. Missing settings stay in an unknown group. Matched comparisons calibrate each qualifying run separately.

Estimated score

Estimated score combines direct scores and calibrated estimates at their full weights. Results with no measurement or estimate count as 0 at their full weight. A direct score or an estimate qualifies a model to rank.

The AI Index uses Version-based estimation. For a benchmark with index weight W, each scoring version a has a share pa and score sa. The benchmark contributes W × Σ(pa sa) to the index score. The version shares add up to 100%.

Score range

Score range uses 0 at the lower end and 100 at the upper end for missing measurements. Both ends use the measured scores where available. Models rank by the lower end.

Measured coverage

Coverage is the share of weight with measured results on selected versions. A faded tile in the score preview marks a missing measurement. That slot contributes its estimate or 0 in Estimated score.

Benchmark versions

Each community scoring choice carries that person’s benchmark weight. BenchPoll splits the benchmark’s weight among versions in proportion to those choices. If nobody chose a version, the primary version gets the full weight.

Estimation votes

In Personal Weights, choose a Scoring version in Advanced settings. Under Estimation support, vote on whether two versions may estimate each other. Either version opens the same sitewide vote. Tap the same thumb to clear it.

Each pair counts votes from the last 72 hours, including older votes to reach ten when available. Versions of the same benchmark are eligible by default, including with no votes or a tie. A majority against excludes it. Your own vote takes priority for your personal ranking.

Choose Nominate a version from another benchmark, then pick a version in Evaluation items. This adds one support vote. Both versions list the pair while its sample has at least one supporter. Select the nomination button again to leave the picker.

How versions predict a missing score

BenchPoll fits eligible measured versions of the same benchmark together. Each link needs paired scores from at least one other model under the same run settings. A model measured on A and B can contribute without C. Sparse samples favor a shared starting correlation. Extreme scores have less influence outside the observed source range.

When direct pairing is unavailable, C can predict A through B. Each link follows the pair vote. Every version must be eligible for A. BenchPoll chooses the shortest path and breaks ties by the number of paired models on the weakest link. Score details show each link.

External sources come last. Public predictions must beat the training median on held-out models in both mean absolute and root mean squared error for that direction. Personal rankings can use one paired model.

Best performance uses the highest qualifying run prediction. Matched comparisons average predictions within each matched control setting and give settings equal weight. Without a connected measurement, A contributes 0 at its full weight.

Publishing and contributions

Publish a topic

Choose Public or Private when creating a topic. Public topics appear as soon as you publish. You can have up to three public topics at a time. To publish a private topic later, choose Make public in its editor.

Make a public topic private before deleting it. Open your profile to create a topic or choose Settings to edit your details and privacy choices. Showing a GitHub link is optional.

Check scores and contribute

Open a model for measured results and estimates. All scores includes other results and their sources. Use Change information to report errors, or contribute sourced scores.
