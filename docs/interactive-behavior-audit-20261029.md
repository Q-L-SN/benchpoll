## 1. 用户、页面与权限

### 1.1 可以不登录完成什么

访客可以访问首页、公开主题、基准介绍、榜单、讨论、提案大厅、使用说明和政策页面，也可以临时调整个人权重并查看预览。临时权重放在当前浏览器标签页的 `sessionStorage`；为了计算预览，权重会发送给服务器，但不会作为已登录用户的个人 pie 保存，也不会计入 Public Weights。浏览器存储不可用、标签页被关闭或会话失效时不能保证保留草稿。

登录、发帖、投票、创建私有主题、提交贡献、保存账户权重和修改资料需要账户。隐私请求可以不登录提出。访客调整 pie 不要求先勾选条款；提交账户行为时会检查当前条款状态。

依据：[访客草稿](../public/js/workspace/guest-drafts.js)、[预览与保存](../public/js/home-workspace.js#L2549)、[API 权限](../server.js#L474)、[条款](../private/terms.html#L57)。

### 1.2 登录与账户

登录目前使用 GitHub OAuth，没有站内密码登录。登录页的继续按钮同时表示同意所列使用条款、知悉隐私政策并确认年满 16 岁及具备使用资格；不是一组独立的隐私处理全面授权。GitHub 必须提供已验证邮箱，优先使用已验证的主邮箱。GitHub 授权失败、缺少已验证邮箱或状态过期时登录不能完成。

首页和配置页使用共用个人中心：显示账户、编辑公开名称和头像、开关公开 GitHub 主页链接、进入隐私与账户选项、退出或停用。默认名称与头像来自 GitHub；自定义后用于支持显示作者的公开位置。GitHub 主页公开开关默认关闭；开启且身份可用时，公开显示处可链接到 GitHub。

退出可以选择设备范围；停用不是彻底删除：会结束会话并删除比较配置等部分数据，但账户关联记录、已保存权重、私有主题、贡献和必要审核记录可能保留。重新通过 GitHub 登录会重新启用账户；访问、更正或删除等请求走独立隐私请求流程。贡献页目前还有自己的账户弹窗，不应假设它与首页个人中心具有完全相同的操作。

依据：[登录页](../private/sign-in.html#L18)、[邮箱选择](../server.js#L279)、[个人中心](../public/js/shared/account-center.js#L41)、[停用处理](../server.js#L1199)、[政策说明](../private/terms.html#L113)。

## 2. 首页

### 2.1 主题目录、导航和搜索

首页显示品牌及介绍，下面是主题卡片。到达一定滚动位置后显示磨砂玻璃顶栏和其下的显示设置；空间不足时，右侧操作收入同层级的更多菜单，剩余导航保持单行，可横向滚动。配置页移动端顶栏的右侧操作与首页不同，只保留 X 和展开侧边栏等对应入口。

目录包含 Popular、Recent、Mine 和 Search：

- **Popular**：按最近 14 天有有效非空个人权重的不同用户数量衡量热度，不是浏览量。Intelligence 按固定主题 ID 置顶。部分七天内的新公开主题可在普通主题序列中获得探索位置，但有前提，见问题 F-04。
- **Recent**：基于本浏览器的浏览记录；Intelligence 存在时仍被置顶。
- **Mine**：登录后显示已配置主题和自己拥有的私有主题，并提供创建私有主题入口；不是“我提交的公开提案”列表。
- **Search**：展开单独的主题搜索框，按主题名称或简介匹配。

卡片按设备空间布局。卡片展示主题名、一句话简介、权重树图以及模型柱；私有主题只对拥有者和授权运营处理可见。点击卡片进入主题；点击具体模型柱则携带当前分数模式和参数区分状态，进入主题后定位并短暂高亮对应模型。点击或拖动翻页控件本身不会被当作打开卡片。

首页的模型搜索选择一个模型或当前启用的参数组合后，包含该结果的可见主题卡片分别定位并高亮；卡片预览和定位会按可见性异步加载。某个主题没有该模型或加载失败，不代表其他卡片也没有。

依据：[首页控制与加载](../public/js/topics-home.js#L26)、[目录与链接](../public/js/topics-home/layout.js#L30)、[热度](../topic-popularity.js#L3)、[主题列表](../topic-service.js#L82)。

### 2.2 显示设置和卡片图形

默认是 **Available results**，也可以切换到 **Score range**；可分别开启 effort 和 harness 区分。开启后同一模型可按所选运行参数拆成多个比较对象。显示方式可以在模型柱加背景权重树图与只看权重之间切换。

首页的 Available results 柱高以该卡片的第一名为参照，不等同于把第一名的绝对分数改为 100 分；分数文本仍是计算结果。模型柱按厂商色显示，左右分页和触屏横向滑动可查看其他模型。权重树图的面积代表权重比例；极小块会并入 Other，文字受空间限制可能只显示一部分。树图、柱高与显示文字并不是另一个独立排行榜算法。

## 3. 主题配置页

### 3.1 侧边栏、上下文和主题身份

桌面首次进入时侧边栏默认关闭；用户后来开关状态保存在浏览器本地。打开后可以浏览热门、近期、我的和搜索等目录，选中其他主题会切换工作区。移动端通过抽屉打开，且不显示桌面的 Back to topics。侧边栏收起时，内容保持受约束的宽度并居中，品牌标识转移到页首。

主题标题附近显示简介，公开主题也可进入讨论。不同主题可以配置若干上下文维度，例如实时、输出形式或参考内容。各维度独立选择：前一维为“未指定”时，后一维仍可选具体值；修改一维不会清空其他维度。历史级联锁定问题及修复见 F-02。

公开主题是平铺的独立主题，不再是对用户呈现的固定父子树。公共主题暂不把其他主题作为动态引用扇区；这是明确保留给未来的功能，不是一次加载失败。

依据：[侧边栏状态](../public/js/shared/config-sidebar.js#L1)、[上下文选择](../public/js/shared/context-selection.js#L1)、[服务端上下文校验](../ranking-service.js#L208)、[主题模型](../topic-service.js#L53)。

### 3.2 Public Weights 与 Personal Weights

公开主题可查看公共权重或个人权重。个人权重由用户选择基准版本、调整扇区占比，并可删除、撤销或配置后备链；交互手势结束后，登录用户的修改会保存，保存失败或账户发生变化时界面会提示并保留可恢复草稿。未登录用户得到的是上一节所述的临时预览；登录后是否采用该草稿需要明确执行保存，不能仅因登录就当作已发布。

每个非空 pie 的权重总和是 100%；存储使用 10,000 个基点，单项最少 100 基点，即 1%，最多 100 项。不同上下文各有自己的个人配置。私有主题没有公共权重或公开讨论，也不计入公开主题的公共聚合。

选择一个扇区或对应基准后，桌面用户可在适用区域滚动调整，触屏用户可在饼图上拖动；只有一个扇区时不存在与其他项重新分配的空间。添加首项时它占 100%；继续添加时，新项通常从最多 5% 开始，其余权重重新分配。移除项目也会把剩余项重新调整到 100%。选中某个扇区可以进入其详情或后备编辑，退出调整状态后滚轮恢复普通浏览；撤销针对当前的编辑历史，不承诺是跨设备的永久版本历史。

公共权重不是所有历史配置的简单平均。系统先匹配主题和上下文：当前维度选择为中性选项时，该维可匹配不同具体值；选择具体值时只匹配该值。每组需要至少一个最近 14 天仍有效的非空 pie 才有影响；样本优先使用最近 72 小时的 pie，少于 10 个时取该组最近至多 10 个有效 pie；不同上下文再按最近 14 天的有效活跃数量加权。补足样本时可能使用更旧的 pie，因此不要将其理解成“只取最近 72 小时”或“每个历史 pie 永远等权”。没有有效近期影响时会得到空的公共权重。

依据：[调整与保存](../public/js/home-workspace.js#L820)、[个人 pie 校验](../ranking-service.js#L25)、[公共权重匹配与采样](../ranking-service.js#L449)。

### 3.3 基准与后备链

一个扇区对应一个基准测试条件或版本。个人权重中可设置有顺序的 fallback：先尝试扇区本身，再依次尝试指定后备；“所有其他版本”代表按规则继续尝试其他合适版本，而不是同时平均这些版本。编辑时可添加、移动或移除链条成员。公共权重会保留贡献者各自的完整后备组合及其占比，计算时按相应组合分别解析，不简单地拼成一条共同链。

Artificial Analysis（AA）相关基准和条件仍可用于浏览和查看原始数据，但不能添加到当前排名计算；自动枚举其他版本时也会跳过 AA。已有 AA 扇区已在本次发布时从受影响的个人 pie 移除并按剩余项重新分配，原始数据没有删除。当前排除主要依赖名称/键识别，局限见 F-06。

依据：[后备操作](../public/js/home-workspace.js#L1282)、[计算解析](../ranking-service.js#L997)、[AA 判定](../public/js/shared/aa-ranking-policy.js)。

### 3.4 模型排行榜与分数详情

排行榜根据当前权重、比较参数和分数模式生成，结果按实际可比性及分数排序；找不到可比实际证据的模型不会冒充有分数。可搜索模型或当前启用的参数值并定位到对应项。effort、harness 开关改变比较分组，因此切换后结果和排名可能变化；同名模型的不同配置不一定是同一个比较对象。

打开模型分数详情后：

1. **Used in this ranking** 展示本次排名实际采用的证据及相关 fallback；可以在当前视图展开。
2. **All scores** 按模型配置、基准与版本展开已批准成绩；当前启用的参数限制会过滤不匹配的配置。
3. 搜索会根据当前层级匹配配置、基准、版本或来源；匹配版本时显示其所在配置。具体记录可展开查看原始分数、来源及编辑入口。
4. 相同数值的多个来源仍保留，但计算该组中位数时同一数值只计一次。已登录用户可以通过编辑图标提出修正，修改需审核。

依据：[模型分数详情](../public/js/workspace/model-scores.js#L57)、[证据与编辑](../public/js/workspace/model-scores.js#L282)、[排名计算](../ranking-service.js#L1125)。

基准发现区允许搜索和浏览基准/版本；当前个人 pie 中已有的项目可定位或移除，尚未加入的项目可添加。已知低覆盖和其他版本有单独的列表分组。列表及排行榜按页加载，空结果与加载失败是不同状态；请求失败时保留已有结果并提供重试，不应把“暂时没有加载成功”解释为“数据库没有数据”。

### 3.5 Available results、Score range 与覆盖率

每个实际结果先依据对应条件的分数方向、上下界或目标值转换为可比较分值。两种模式使用相同的个人或公共权重、实际成绩和 fallback：

- **Score range**：已取得实际结果的权重贡献确定；缺失项的下界按 0、上界按 100 计算，展示可能区间，不用区间中点伪装成实测。
- **Available results**：优先直接实测，其次有序 fallback；都没有时尝试基于其他模型和基准的两两比较预测。无法估计的权重不参与该模型当前可用部分的平均；完全没有真实覆盖时不生成可用结果。真实直接/后备成绩才算真实覆盖，预测不算。
- 当前版本对可用部分平均分的非负结果乘以 `5c/(1+4c)`，`c` 为真实覆盖比例；负分采用镜像处理，避免低覆盖让负分反而变好。显示四舍五入不代表后台把所有原始分数取整。

当前预测并非实测。它对共同测过的版本建立模型间相对能力关系，再用目标版本的已有实测进行单调校准；连接不足或拟合失败时不预测。2026-10-30 的后续修复对少数孤立的极端参照限制其校准影响，仍生成有足够关联证据的预测，不改动真实成绩，也不构成置信区间。公共和个人排名使用同一类推断，但权重、上下文及 fallback 可以不同。实测、后备和推断的可靠程度不同，不能把 Available results 分数直接解释为模型在所有基准均已实测。

依据：[分数归一化](../ranking-service.js#L860)、[两种计算](../ranking-service.js#L997)、[覆盖计算](../public/js/shared/available-score.js#L99)、[两两比较](../pairwise-score.js)。

## 4. 基准详情与讨论

### 4.1 基准详情

从基准入口进入详情后，默认显示 Discussion；All scores 显示该基准的成绩和版本选择。成绩按原始数值从高到低分页排列；如果某个版本是“越低越好”，这个显示顺序不等同于表现从好到差。Change information 外观与选项卡统一，但实际跳转到修改表单，不是本地显示面板。基准标题只有存在有效的 HTTP(S) 官方 URL 时才会在新标签页打开；无效或缺失 URL 不生成外链。

基准版本列表、得分来源及条件可能属于同步来源；同步条件不能直接手工新增成绩，现有成绩仍可从详情提出纠错。AA 原始条目仍能查看，但不参与排名。

依据：[基准详情实现](../public/js/discussion.js#L58)、[基准分数排序](../benchmark-scores.js#L30)、[手工成绩条件](../public/js/contribute.js#L690)、[已批准分数 API](../server.js#L790)。

### 4.2 讨论的范围、读取和写入

公开主题的讨论可按主题/上下文查看，也可在基准详情中查看与基准相关的讨论；界面支持在当前类别和所有类别范围之间切换。列表可以按 Hot 或 New 排序，并在接近列表底部时自动加载下一页；自动加载失败应允许重试。Hot 使用净支持数和发帖时间衰减，并非人工审核排序。

登录用户可以发主题帖、回复、支持、反对、取消投票、删除自己的内容，以及举报讨论。不能给自己的帖子投票；回复挂在根帖下，不是无限嵌套。发帖内容去除首尾空格后至少 2 个字符，原始内容最多 4,000 个字符，最多引用 10 个基准/版本；同一账号发帖有 30 秒冷却和滚动 24 小时最多 100 条的限制。删除自己的帖子会清空正文和引用；若根帖仍有回复，列表可保留“已删除”占位以维持上下文。举报通过私有审核处理，不会自动隐藏内容。

从某个基准进入讨论时，范围切换只改变查询的主题范围，并不修改该基准、用户当前权重或已发表内容。打开一个根帖可看其回复；加载新页、切换排序或范围与发帖是分开的操作。讨论内容中的基准引用必须是有效公开基准或可选版本，失效引用不能作为新的合法引用提交。

依据：[讨论规则](../discussion-service.js#L13)、[写入和投票](../discussion-service.js#L45)、[列表排序与范围](../discussion-service.js#L160)、[自动加载](../public/js/shared/discussion-auto-load.js)。

## 5. 新主题和提案大厅

### 5.1 私有主题

登录后从 Mine 发起创建，填写名称和必填的一句话简介。服务端校验名称、保留路径和输入；名称不应被当成具有特殊权限的标识。创建后立即属于创建者，可以配置自己的 pie；私有主题不进入公开聚合或公开讨论。公开创建不能绕过提案审核直接使用同一个创建 API。

依据：[主题校验与创建](../topic-service.js#L35)、[公开创建拦截](../server.js#L598)。

### 5.2 公开提案的实际状态机

大厅有全部与 In review 视图；按页加载。登录且有已验证 GitHub 邮箱的用户可以提交主题名和简介。同一账号在征集中最多拥有一个提案；最多同时支持 **3 个**其他人的征集提案，不能支持自己的提案。这两个额度的口径已确认，见 F-03。

提案从创建开始征集 14 天；在仍征集中时作者可以修改或撤回，修改会清除已有支持票，原截止时间不因修改重新开始。撤回会删除提案及其支持票，不再作为 Withdrawn 列表项；到期未达标显示 expired，不能继续投票。达到 30 名不同支持者后进入 pending/In review，管理员审核通过才创建公开主题，拒绝则不创建。进入审核后不再按普通征集状态编辑、撤回或投票。审核结果会进入通知队列，面向 GitHub 已验证邮箱；加入队列不等于邮件已经送达。

用户此前明确提到的赞助直上功能尚未实现；公开提案的作者也不以“赞助创建者”身份显示。过期和被拒绝的提案不再永久占用名称，详见 F-01。

依据：[提案常量与状态](../topic-proposal-service.js#L9)、[提案与列表](../topic-proposal-service.js#L167)、[支持与送审](../topic-proposal-service.js#L220)、[撤回与编辑](../topic-proposal-service.js#L245)、[通知队列](../moderation-email.js#L209)。

## 6. 贡献和反馈

### 6.1 可以提交什么

贡献入口包括新增基准、模型和分数，修改或请求删除已有基准/模型/分数，以及基准纠错、普通反馈和讨论举报。不同入口打开对应表单；从具体对象进入时会携带预填上下文。预填通过短时本地交接保存，不是永久可分享的完整表单数据；失效后应从原页面重新打开。没有账户可以看表单入口，但实际提交需登录并接受当前适用条款。

新增基准需检查是否已有同名对象，可描述版本、评分方向、分值范围和来源；可请求官方来源自动同步，但勾选请求不等于同步已被配置或已经运行。新增模型先选厂商；空搜索时厂商建议按已有模型数量排序，也可录入新厂商。当前新厂商可没有 logo，届时使用回退标识；不是要求用户一定上传 logo。

新增分数需要选择模型、基准版本、分数及来源 URL；可以批量录入表单中的多条分数。用户可选的固定运行字段为 effort 和 harness，值来自已批准选项，不再提供自由新增任意字段的入口。系统会显示正在审核的相关对象并防止与同步条件冲突。修改和删除是**提交审核请求**，不会在点击提交后立刻修改公开数据。

“Request bulk import”实际打开预填指导的反馈表单，供人工处理；它不是文件上传器或自动批量导入流程。普通反馈/举报的引导文字显示在输入框外，提交时与用户填写内容组合。提交成功表示已接收，不表示已经审核通过，也不保证通知邮件已经送达。

修改基准时可请求修正资料、补充版本或合并重复项；修改模型时可请求更正或报告重复项；修改成绩时可针对已经批准的证据提出更正或删除。删除请求在审核通过前不会立即移除线上对象。可使用的具体字段、必填项和选择条件取决于当前表单及目标状态，服务端会再次校验，不能仅依赖客户端隐藏或禁用按钮。

依据：[贡献表单模式](../public/js/contribute.js#L75)、[批量导入请求](../public/js/contribute.js#L42)、[厂商排序与创建](../public/js/contribute.js#L506)、[分数字段](../public/js/contribution/score-fields.js#L11)、[提交 API](../server.js#L4230)。

### 6.2 审核及邮件

审核员可以查看队列、数据和审核记录，并处理可批准或拒绝的贡献、上报、更正、同步冲突等；高级审核员另有更高权限操作。具体权限由服务端检查，隐藏按钮不是唯一保护。审核通过后相关变更与审核记录按相应事务流程写入；需要通知时写入邮件 outbox，由后台发送并处理失败/重试。

Resend 域名已验证，用户此前确认过一次单独的发信测试和隐私/支持地址收信；这不能证明每一次审核通知都成功送达。本次审查没有替用户实际提交并审核每种类型，也没有把队列里的记录视为已发送。若用户没有收到，应分别检查对应审核结果、outbox 状态、发件服务与垃圾邮件，而不是只看提案状态。

依据：[审核接口](../server.js#L4798)、[审核应用](../server.js#L5190)、[通知发送与失败处理](../moderation-email.js#L209)。

## 7. 隐私、信息和边界

政策页面说明访客草稿、公开聚合、账户、讨论、贡献、设备存储和隐私请求。`privacy@benchpoll.com` 用于隐私联系，`support@benchpoll.com` 用于一般联系；未登录用户也可提交私有隐私请求。当前政策明确写出运营者位于中国大陆，并说明尚未公开运营者法定姓名和邮寄地址。用户此前对公开所在地有顾虑：这是真实现有文案，不应误说它已经删除；是否应披露、是否需要其他资料，要结合实际主体和适用地区单独由专业人士判断，不能简单断言“有邮箱就一定合规”。

隐私请求页面要求联系邮箱、请求类型和说明，类型包括访问、更正、删除、反对处理及其他；不要求登录。提交只建立待处理请求，不自动验证邮箱、发送回复或删除数据。高级审核员可查看队列并记录 open、in review 或 closed 状态，但保存处理记录也不会自动发邮件；运营者必须另行核实身份并跟进。账户页中的条款确认和资格确认分别需要勾选，和隐私请求表单互不依赖。站点当前不提供把私有主题数据用于研究的开关。

此前政策与实际实现的部分陈旧描述已更正，见 F-05；这些更正不等于对适用法律的合规结论。账户停用、隐私请求、政策确认和公开 GitHub 开关是不同操作，不能互相替代。

依据：[隐私政策](../private/privacy.html#L59)、[使用条款](../private/terms.html#L51)、[隐私请求界面](../private/account-privacy.html#L67)、[隐私接口](../server.js#L474)。

### F-01：到期提案占名

修复前：

1. 用户提交一个公开主题提案，14 天未达到支持门槛。
2. 系统将它视为 expired，用户不再能编辑或撤回。
3. 创建提案时的同名/同 slug 查询没有排除 expired 记录，数据库还保留对应唯一约束，因此再次提交同名提案返回 `topic_proposal_exists`/HTTP 409。

修复将名称占用与历史名称分开保存：已到期或被拒绝的提案释放占用，允许重新提出，同时保留原提案、票数和审核记录；进行中的提案仍受唯一约束。当前用户主动撤回则按既有规则删除提案及其票数。并发创建、编辑、历史信息以及真实 MySQL 隔离数据库迁移已测试。

依据：[有效状态和操作限制](../topic-proposal-service.js#L32)、[同名检查](../topic-proposal-service.js#L180)、[测试夹具](../test/helpers/topic-proposal-limits-fixture-20261028.mjs)。

### F-06：AA 判定来源不够结构化

目前客户端和服务端共用名称、键等启发式规则过滤 AA。它能覆盖本次确认的数据，但新导入数据改名、条件名称未包含 AA 信息、或独立条目的名称只是提到了 Artificial Analysis，都可能带来漏判或误判。这里是根据实现推导的风险，不等于已找到线上具体误判。

建议为基准、条件和必要的成绩来源引入可审核的结构化来源/排除标识，让导入器、选择器、fallback 与排名共用同一事实，并测试改名、混合来源和历史数据迁移；不要通过删除 AA 原始成绩解决。

依据：[AA 规则](../public/js/shared/aa-ranking-policy.js)、[计算排除](../ranking-service.js#L1009)。

### F-07：估分精度与覆盖盲区

本次使用排除 AA 后的线上数据快照做**只读遮蔽回测**：进行 5 轮确定性遮蔽，每轮对 1,094 个满足最低条件的模型分别选一个完整基准，并同时移除各自该基准的全部版本，再拟合和预测；共 5,470 个案例。同一个模型多次出现，不是 5,470 个独立模型。在两种算法都能给出预测的 5,410 次中，加入敏感性保护之前的两两比较平均绝对误差约 4.39 个标准化分数点，更早的百分位方法约 4.89；前者约 12.6% 的误差超过 10 点。剩余可用测试版本不超过 5 个的 818 个共同案例中，两两比较平均误差约 5.15 点，百分位方法约 4.84 点。

这些数字是被遮蔽的**单个基准标准化分数**误差，不是最终综合分数或榜单名次误差；样本偏向已有足够数据的基准和模型，不能代表冷门模型、未来模型或非随机缺失。模型能力被压缩到一个相对位置，专长差异、测试设置不一致和少量目标参考都可能导致偏差；目前没有逐次预测的可靠置信区间。建议将“真实/后备/估计”继续分开展示，增加按覆盖度和基准拆分的回测、时间外验证与不确定度，避免用预测替代补测。

复核 ARC-AGI-3 时，站内样本的 17 个已测模型包含一个接近 100 的极高参照；此前 Gemini 3 Deep Think 和 GPT-5.4 Pro 分别被估到约 99.95 和 95.79。移除该参照后重新拟合，两个估计都变成约 32.60，证明结果对单个参照高度敏感；32.60 也不是这两个模型的实测分数。上一版过度保守地将这些估计置空；后续修正为仍然估计，对分布边缘最多三个、与主体间距足够大的极端参照，只在构建校准曲线时软限制其影响，实际分数及参照分布不改。只有两个或三个参照时不尝试自动判断离群。该规则是启发式，不保证正确识别真正的特殊表现，也不等于统计置信区间；对真实高性能模型可能低估。

使用同一快照和相同遮蔽案例复测，新方法仍能预测原来的 5,410 个共同案例，平均绝对误差约 4.37 点，之前约 4.39 点。其余 60 个两两比较案例仍因证据不足等原因未解析；比较对象是同一批案例，但差距很小，不代表所有基准都更准确。该抽样没有包含 ARC-AGI-3，且只涵盖实测模型数不少于 10 的目标版本。

### F-10：ARC-AGI-3 的实测数据滞后

站内快照缺少 GPT-6.1 Sol 在 ARC-AGI-3 的成绩，但官方结果页已发布该模型在 Standard 与 Provider Adapter 下不同的实测值：[ARC 官方结果](https://arcprize.org/results/openai-gpt-6-1-sol)。推断不能替代对这些成绩及其 harness、effort、来源和版本的及时采集；旧的 ARC 专用脚本只覆盖 v1/v2，当前 v3 导入不是经验证的持续自动同步。尚未安全核对模型映射、去重和来源更新前，不应将脚本直接用于批量写入或声称已经同步。

个别测试使用提取源码片段并注入全局变量、或直接匹配 HTML/CSS 文本的方式，新增真实依赖或调整共用组件时容易出现与用户行为无关的测试失败。本次共享顶栏和 AA 规则改动就需要同步修正这类测试夹具；不应因此移除测试，而应逐步补充稳定的模块接口测试和真实浏览器行为测试。

建议顺序：先给上下文、提案状态机、评分与邮件 outbox 建立明确契约和回归测试；再拆出纯计算、仓储/事务、交互状态机及独立表单；最后基于调用证据清理旧路径。拆分过程中保持现有 URL、权限、幂等性和错误恢复行为，不做一次性大重写。

## 9. 已知产品边界，不直接判为故障

- 动态引用其他主题的 pie 扇区尚未实现；当前也没有用其他机制冒充该功能。
- 赞助主题、付款和赞助后直接上线尚未实现。
- 私有主题没有公开讨论和公共权重；访客草稿不自动变成公开投票。
- Request bulk import 是人工请求，不是自行上传文件的批量导入。
- 旧高级比较筛选不在当前主界面；历史兼容代码是否删除需单独确认。
- AA 内容可以浏览，但按现有政策不作为排名输入。
- 停用账户不是自动全面擦除；隐私请求需要人工处理。
- 个人公开 GitHub 链接由用户开关控制；公开提案作者不会因此自动成为公开主题署名。

- 本次发布后健康检查通过；桌面及移动端浏览器测试覆盖共享顶栏、主题搜索、配置页、基准选项卡、分数编辑入口和部分账户交互。

- F-01 使用隔离的提案测试夹具和模拟时间；F-02 直接运行上下文选择函数。没有为了复现而创建或修改真实用户提案。
