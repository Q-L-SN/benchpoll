## External Information Required

The owner must choose an authorized SMTP service and provide these through a
secure configuration channel, not a committed file or a public conversation:

| Variable | Production State | Required Information |
| --- | --- | --- |
| `BENCHPOLL_SMTP_HOST` | Missing | Provider's SMTP hostname |
| `BENCHPOLL_SMTP_PORT` | Missing | Provider's SMTP port |
| `BENCHPOLL_SMTP_USER` | Missing | Authorized SMTP username |
| `BENCHPOLL_SMTP_PASSWORD` | Missing | SMTP-specific password or credential |
| `BENCHPOLL_NOTIFICATION_FROM` | Missing | Provider-authorized sender address |
| `BENCHPOLL_SMTP_SECURE` | Missing, optional | Explicit `true` or `false`; otherwise port 465 defaults to `true` |

The application currently implements SMTP delivery, not a vendor HTTP email API.
An HTTP-only API key cannot replace the SMTP group without a separate integration.
Provider-specific sender/domain authorization, account restrictions and delivery
permissions cannot be assessed until the provider is known.

## Local Patch

- `moderation-email.js`: missing-setting errors now name only the absent
  variables. The new inspection export uses the existing validation and returns
  only presence states, a configuration flag, and sanitized validation messages.
- `scripts/check-moderation-email.mjs`: a configuration-only CLI. It loads `.env`
  quietly, does not create a transport, connect to SMTP, access a database, or
  start a worker. Exit code is 0 for complete valid configuration, otherwise 1.
- `test/moderation-email.test.mjs`: configuration/redaction/CLI regression tests
  and a twice-repeated check that an unconfigured service never accesses or
  schedules delivery against the queue. Existing account-ID changes are preserved.

From the application directory:

```powershell
node scripts/check-moderation-email.mjs
```

`deliveryConfigured: true` means only that configuration validation passed. It
does not prove connectivity, authentication, provider acceptance, or delivery.
The CLI explicitly reports `smtpConnectionVerified: false` and
`mailWorkerStarted: false` even when configuration is complete.
